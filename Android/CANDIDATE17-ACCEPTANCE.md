1. **Authoritative normal dirty rejection.** On a fresh unused worker, root supplies an existing interrupted record ID. Run `-e class org.un1box.android.GuestDirtyAdmissionTest#normalStartRejectsActualDirtyMarkerWithoutChangingRetainedMetadata -e rejectDirtyStart true -e recordId <native-id>`. It never calls recovery or synthesizes a marker. Existing Binder API returns error text, not numeric status; the receipt labels code6 source-expected and numeric status unobserved. Overlay payloads are not rehashed; metadata equality is not a claim of byte-for-byte large guest-data verification. Keep `dirty-admission-evidence-*`. The frontend's disabled Start button for known-dirty metadata is a separate UI check and cannot replace this native rejection test.
