# Explicit recovery of interrupted Android guest state

Normal `Native.start(root,id)` and `IEngine.start(id)` retain their existing signatures and now use the JNI owner's fixed `allow_dirty=false` admission. A dirty state marker means the previous guest shutdown was not confirmed; ordinary Start must reject it. Root/domain own the marker and lease policy. No UI/service code clears a dirty marker or repairs/copies guest assets.

The separate `Native.recoverStart(root,id)` and trailing `IEngine.recoverStart(id)` select the JNI owner's fixed `allow_dirty=true` route. Callers do not pass a boolean, path, machine or boot arguments. Both operations consume a fresh unused worker; disposing or already-consumed workers return an actionable error. Recovery cold-boots the selected record using retained writable data and private diagnostics. It does not infer or retroactively confirm the previous shutdown. Only the domain's existing confirmed halt/engine-exit path clears the marker.

The activity exposes the semantic **Recover retained state** action (`recover_guest`). Ordinary Start is disabled when the selected record metadata already reports dirty; native admission independently checks the authoritative marker. Recovery remains available for an inactive selected device even when a prior worker death left the displayed metadata stale. The pending request holds both record ID and explicit recovery choice across disposal/binding, so a later library refresh cannot redirect recovery to a different record or silently convert it to ordinary Start. The action still uses the existing fresh-worker restart flow when an old service session was consumed.

`GuestQmpSnapshotTest` adds an opt-in `-e coldRecover true` only for a fresh-worker start, using the new explicit Binder operation. It rejects that flag with `snapshotOnly`; reading an existing endpoint cannot perform cold recovery. Default test start remains ordinary Start, and both cases keep boot/diagnosis acceptance flags separate. This new hook requires the matching main/test APK that includes the appended method; immutable candidate16 and its isolated16c concurrent-test variant do not acquire it.

JNI changes are owned by graphics commit `e40523d27777729c1a87b96377d39e3bc098d67c`; product changes contain only Kotlin/AIDL/UI/test/docs. Root integrates and freezes the combined source before compilation. Acceptance still requires actual ordinary dirty-state rejection, intentional recovery with retained data/diagnostics, clean halt and subsequent ordinary same-state reboot. Source review alone is not that target proof.
