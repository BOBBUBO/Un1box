# Private actual-guest cache exploration controller

These host scripts prepare and control one allocated Linux n72 guest
exploration. They are diagnostic tools, not a shipping cache feature or a
firmware download/preparation route. Cache defaults off. Actual Home/Settings
inspection and a fresh exact-packet Root grant are required; no frame counter
or image heuristic creates a scene pass. Preserve each failed packet/run.

Deploy the eight production Python helper sources alongside the privately supplied `PLAN.json`
and artifact/receipt paths. Run `prepare-exploration.py --lock-policy` with the
existing audited `Linux/scripts/lock-continuity.py`. Preparation inventories
the existing immutable base, copies only small writable state using independent
inodes, and records actual executable/dependency pins. It does not start a guest
or GUI. Never commit generated inputs, state, inventories or private captures.

`EXPLORATION-TOOLS.json` binds the resolved absolute Xvfb, xdotool and ffmpeg
executables. The controller and capture helper use these paths and verify their
hashes; service PATH is irrelevant. PNG conversion is a three-second bounded
host operation. Its success says nothing about the image's guest scene.

The first private packet failed because its capture converter used bare
`ffmpeg`, which was missing from systemd's PATH. All actual BMPs were retained;
Home129s expired and ordinary shutdown was clean. The correction keeps that
failure and requires a separately granted successor. It does not turn prior
BMPs or a successful host conversion test into guest acceptance.

Run host contracts with a real local ffmpeg available through the initial PATH,
or set `LT_CACHE_TEST_FFMPEG` to its exact executable path:

```sh
python3 tools/cache-exploration/test-exploration.py -v
```

A private deployed packet also sets `LT_CACHE_TEST_LOCK_POLICY` to the exact
pinned `Linux/scripts/lock-continuity.py` used by that packet.

The converter regression runs the actual executable with PATH nonexistent and
with a conflicting basename. The rest exercises filesystem inventories, PIDFD
retirement, strict clean-stop fields, finite cgroup/grant policy, actual88px
toolbar geometry and retained-image continuity. These are host contracts only.
Read the private packet's `RUN-EXPLORATION.md` for its allocation, invocation,
source manifest, operator capture/inspection steps and independent retirement.

The second actual run produced a personally viewed complete Earth Lock, but
model/tool turnaround outlasted its awake window; fresh sleeping status correctly
blocked slider input. `prepare-exploration.py` can now pin that prior private
capture with `--lock-reference DIRECTORY --model-inspected-reference`, after
actual personal PNG inspection. It binds full BMP/PNG/receipt hashes and the
original fresh awake receipt; the reference may belong to an earlier worker.
It never substitutes that old worker identity for the current live owner.

In a separately granted successor, `exploration_control.py home-unlock
--model-inspected --output lock-unlock01` performs one balanced Home, immediate
bounded current-worker awake/frame wait, capture, fresh awake diagnostics and exact Earth/slider-knob/lock-
symbol comparison, followed by one balanced slider. Input is bounded by eight
seconds and the unchanged original Home129s deadline. Conversion happens after
input; full captures, exact region receipts and failed admissions are retained.
No external model/tool roundtrip occurs inside the awake admission. Personally
inspect the retained post-input PNG before any Home attestation or Settings tap;
anchor matching never recognizes Home or creates guest acceptance. No cache
correctness or speed claim follows from these controller contracts.

After balanced Home the helper polls telemetry for at most2.5seconds, reserving
four seconds before the existing input/Home129s deadline for capture and slider.
It requires a fresh awake RUNNING status and a source frame produced since that
Home input began, including frames produced during the balanced key pulse. It
rechecks current worker identity on each poll and retains every observation.
This wait sends no additional Home, Power or touch input and never changes the
reference pixels, exact anchor policy, personal scene gates or original clocks.
The subsequent actual capture must independently remain fresh/awake and use a
post-Home source frame. Timeout or identity/state failure sends no slider.

Experimental cache correctness uses a separately frozen and separately granted
successor. Preparation defaults to `--cache-mode off`; it rejects cache inputs
in OFF mode. An explicit `--cache-mode cold --cache-directory /canonical/private`
requires an existing owned0700 directory outside base/seed/state, genuinely empty
before the native worker. Do not modify a previously frozen OFF packet. Reuse
selects the same directory and additionally supplies `--reuse-cache-receipt` for
the prior actual `cache-trial.json` and `--reuse-cache-result` for its matching
actual `RESULT.json`. Both files are pinned into the new source packet. They
must describe a scoped clean retired run of the exact same engine, client,
base identity/lock, ROM, package, clean seed and Home/Settings workload.

The controller scrubs inherited cache variables before applying that explicit
selection. It inventories native record bytes, engine/key/payload checksums,
private inode ownership/modes, single links, native lock availability, directory
identity and bounded record count/bytes before and after. Symlinks, unknown or
interrupted temporary entries, changes to existing records and a still-locked
native store fail closed without repairing or deleting evidence. Actual native
enable telemetry must name the mapped engine digest; monotonic actual counters
must agree with the resulting record count. Cold requires real stores; reuse
requires real hits against the exact prior inventory. Actual personally viewed
Home and Settings at native44,326, strict normal Stop, unchanged base/seed and
independent retirement remain required. These are correctness checks with no
audio. They never establish a speedup or Android qualification. Matched repeated
timings, worker CPU and broader target acceptance remain separate follow-up work.
# Matched shutdown diagnostic

Packet preparation can explicitly select `--matched-shutdown-diagnostic` for an
OFF, fresh COLD or qualified REUSE trial. Ordinary exploration retains its immediate Stop after
Settings inspection. The opt-in mode binds the fixed schedule to packet inputs:
one Home/guarded slider at original HELLO+50..51s, actual Home inspection by95s,
one Settings input at105..106s at44,326, actual Settings inspection by120s, observed
readiness120..135s, and ordinary Stop at180s. Original Home129s/Stop205s ceilings
and native30s shutdown deadline remain unchanged. Missing a window fails the
diagnostic and requests ordinary Stop; no second input or clock reset is allowed.

The Settings inspection command additionally requires
`--wifi-name qemu-ios`, reported from the personally viewed actual image. A
different observed network is an unmatched diagnostic, not a networking pass.
Readiness checks only the exposed RUNNING/agent/awake/shutdown-phase status and
retains every status in its fixed window. It does not establish equality of every
guest service or pre-shutdown storage activity, which that telemetry cannot show.
The shutdown dispatch still must record its actual storage/agent decision.

Schedule receipts preserve the existing strict clean-shutdown/retirement gates.
They establish neither cache speedup nor cause of an earlier shutdown failure.
Each OFF/COLD arm needs its own clean writable seed clone; COLD starts with an
empty isolated cache. A failed dirty trial never supplies a clean REUSE receipt.
REUSE selects that exact retired cache with pinned clean producer receipts,
requires its producer's actual completed matching schedule, and boots another
fresh worker from another clone of the original clean seed. Its native hit count
must increase: an enabled setting or surviving cache files do not prove replay.
Deploy and pin `matched_trial.py` with the other helper modules. Existing frozen
packets and their failed evidence remain unchanged.

## Self-contained image-bound operator

The explicit `--image-bound-operator` preparation option uses the fixed v2
schedule with prior personally viewed `--home-reference` and
`--settings-reference` capture directories and the explicit
`--model-inspected-scene-references` flag. Root must inspect the reference PNGs
before preparation: complete Home with the Settings icon at44,326 and complete
Settings showing Wi-Fi qemu-ios. Preparation binds their BMP/PNG/receipt bytes;
these references are part of the cache workload identity. The ordinary manual
route retains its personal inspection requirements and is unchanged.

The operator runs within the existing finite controller, without model/tool
roundtrips. It sends one guarded Home/slider at HELLO+50..51s, polls actual
coherent awake captures for exact Home-reference equality through95s, and sends
the single Settings tap at105..106s only after a new exact continuity check.
It polls for exact Settings-reference equality through120s. Only clock RGB
pixels129,1..190,19 may differ; alpha, Wi-Fi, rows and all other pixels remain
protected. Wrong images receive no scene admission. Failed input attempts are
consumed, with no retries. BMP/PNG/receipt/comparison files survive failures.
Readiness120..135s, Stop180s, original ceilings and native shutdown30s remain.

`home-admitted.json` and `settings-admitted.json` explicitly record
`model_inspected:false` and `scene_qualified:false`. They never create
`*-inspected.json` files or personal inspection timestamps. Automatic admission
only authorizes the prescribed input. A complete clean runtime yields
`AWAITING_ROOT_REVIEW`, including its provisional cache receipt, with process
exit0; this is not a qualified run. Independent Root review must personally view
the exact PNGs named by the admission records, verify full Home and Settings
with Wi-Fi qemu-ios, and independently check the retired unit/processes.

After actual viewing and retirement, run the deployed helper:

```sh
python3 /absolute/private/packet/postrun_review.py \
  --model-inspected-home --model-inspected-settings --wifi-name qemu-ios
```

It rechecks original source and retained scene bindings, original readiness and
input schedule, strict clean Stop, no disposal, free state lease, original
frontend/worker/controller retirement and absent original cgroup. It writes
separate `ROOT-SCENE-REVIEW.json`, `cache-trial-qualified.json` and
`QUALIFIED-RESULT.json`, preserving the raw pending result/receipts/images.
An existing or interrupted review is not overwritten. REUSE must pin these
separate qualified producer files; provisional or modified derivatives fail.
The original personal-input attestation flags stay false even after review.

Next finite sequence: one new independently allocated OFF packet, then one
COLD packet only if OFF qualifies, then a fresh-worker REUSE packet only after
the actual clean COLD cache and separate Root review exist. Use identical
source/engine/frontend/reference/asset/seed/workload identities, fresh independent
writable clones, the exact unchanged COLD cache for REUSE, and native hits>0.
Stop at the first failed correctness/shutdown/network/image/resource predicate;
do not repeat the failed manual-deadline trials. No enabled run is authorized

## Realistic performance scope

The current experimental cache skips eligible A32 ARM1176 frontend decoding.
TCG still optimizes the IR and emits fresh host native code in each worker.
It stores at most4096records/32MiB and can fill during boot. Every new record
currently performs file fsync plus directory fsync on the vCPU path; COLD can
therefore add substantial storage latency, especially on Android. The capacity
guard avoids impossible save work after saturation but does not enlarge coverage.
There is no basis yet for a dramatic speedup claim or Android delivery claim.

First qualify the same fixed engine's OFF/COLD/REUSE guest correctness and
shutdown. Then measure actual eligible hits/(hits+misses), records/bytes and
when capacity fills, first-lit wall/CPU time, and fresh-worker CPU deltas from
resources.jsonl with command.json's actual clock tick frequency. First lit is
not full Home; image capture/inspection timing provides bounded observations,
not exact scene-load latency. Separately allocated representative profiling
must establish how much CPU time frontend translation consumes versus IR
optimization/native emission, execution, graphics and I/O, and how much COLD
time fsync/store work consumes. Report absolute overhead and sample boundaries;
one warm run is preliminary, not a replicated performance qualification.
Keep cache OFF/unqualified until actual target benefit and acceptance exist.

The v2 schedule wakes/unlocks20seconds earlier to leave45seconds for actual
Home capture and operator inspection. The failed v1 OFF07 missed its original
95second inspection deadline and remains failed. Frozen v1 packets are not
modified or resumed; every v2 arm uses a new packet and original clean seed.
Settings, readiness and Stop times, clean shutdown and reuse requirements stay
unchanged. The schedule remains a diagnostic, not a speed benchmark.

## Retained wake failure diagnosis

`python3 tools/cache-exploration/wake_diagnosis.py /private/packet/exploration01`
reads and hashes the original Home attempt, telemetry, input-command log, result
and cache counters. It emits JSON to stdout and writes nothing to the run. No
guest, display, input, retry or cache access is started. The recorded 2.5-second
awake window remains authoritative; the tool does not renew it or reinterpret
later Stop-generated display changes as a successful Home wake. Test this
offline helper with `python3 -m unittest discover -s tools/cache-exploration
-p test_wake_diagnosis.py -v`.

A failed original window alone does not distinguish slow guest wake, missed
keyboard delivery, frontend scheduling or engine input handling. A recorded
xdotool key pair establishes host command dispatch, not SDL consumption or
guest IRQ handling. A lit frame after shutdown dispatch is contaminated by a
different guest operation. Zero native cache hits exclude replay as the
executed path but do not exclude key/hash/capture/store overhead during COLD.
Retain those distinctions when selecting a separately reviewed diagnostic
packet; never reuse an unqualified failed producer or extend its old clock.
